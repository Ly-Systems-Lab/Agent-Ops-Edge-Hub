# 物理世界数据面规约

> 这是 Agent Ops 三件套里**数据面**（[`Agent-Ops-Edge-Hub`](https://github.com/Ly-Systems-Lab/Agent-Ops-Edge-Hub)）的工程规约。
>
> 总蓝图仓那份[《协同宣言》](https://github.com/Ly-Systems-Lab/Agent-Ops-Architecture/blob/main/docs/manifesto.md)
> 讲的是「人怎么用 AI」；这份规约讲的是另一件事：
> **AI 的意图进入物理世界时，凭什么可信。**
>
> 三件套里，控制面管「谁有权让 Agent 动手」，数据面管「动手这件事本身怎么不出错、不被越权、不互相牵连」。
> 所以这里不重复宣言，只留三条：**可靠 · 安全 · 隔离**。

---

## 一 · 可靠：每个动作都有回执，每次断连都能自愈

**发出去不等于做到了。**

指令下发后必须能拿到"成没成"；拿不到就如实报错，不能默认成功 ——
否则人看到的是"已完成"，设备其实没动。

**为什么。**

- 物理世界的动作**不可回滚**：重发一次不会"更准"，只会多执行一次。
- 对操作者来说，**"没反应"和"成功了"看起来一样**。没有回执，就无法区分这两种情况。
- 节点会掉线、进程会崩、上游会超时 —— 这些不是异常，是常态。系统必须能自己回来。

**怎么检验。**

| 判据 | 本仓的做法 |
|---|---|
| 同一条指令重复到达只执行一次 | `devctl.py` 按 `id` 去重；`p4_agent.py` 有 `Dedup` |
| 拿不到回执不算成功 | 超时回明确错误码（`agent_timeout` / `internal`），不静默丢弃 |
| 单个进程挂了能自己回来 | 全部 systemd 单元 `Restart=always`；paho 自动重连（`p4-agent` 1→30 s 退避） |
| 总线断了设备不变砖 | 设备固件不依赖总线存活，本地功能照常 |
| 设备状态可追 | P4 的 `hub/device/p4/status` 置 retained，新订阅者立刻拿到最后状态 |

> ⚠️ **诚实是可靠的一部分**：没有实测过的事，不写成"已验证"。
> 本仓的机制表逐条给代码位置，见 [ARCHITECTURE.md](ARCHITECTURE.md#三可靠性机制清单)。

## 二 · 安全：唯一被信任的通道，是窄而确定的

**默认不信任任何设备。**

设备通道只走 **TLS 1.2 + 双向证书 + 账号密码 + 按主题收窄的 ACL**；
明文口只绑回环，出不了这台机器。

**为什么。**

- 端侧设备是"被指挥的一方"，它暴露在局域网里、可能被拆开、可能被换掉。
- 凭据泄露不应该等于整台中控被接管 —— 所以每台设备一套凭据、一个角色。
- 通道越窄，越容易验证。宽通道（`#`、匿名、明文）省下的配置，最后都会变成不可审计的入口。

**怎么检验。**

| 判据 | 本仓的做法 |
|---|---|
| 没有客户端证书连不上 | `8883` 开 `require_certificate true`，握手阶段就断 |
| 每台设备只能碰自己的主题 | `acl_file` 按前缀收窄，外部角色**绝不给 `#`** |
| 明文口出不了机器 | `1883` 只绑 `127.0.0.1`（`per_listener_settings true`） |
| 凭据不进仓 | `.env` / `*.key` / `*.crt` / `passwd` 全部 gitignore；仓里只有 `<REDACTED>` |
| HTTP 只是最小闭环 | `5000` 只有 IP 白名单（默认仅回环），**没有认证**；仅限受信网段 |

> 详细配置、ACL 全文与 HTTP 加固路线：[SECURITY.md](SECURITY.md)。

## 三 · 隔离：一台设备的失败，关在它自己的主题里

**不做「万能路由」。**

每台设备一个适配器进程；走 MQTT 的设备再各有一套凭据和 ACL 角色，
主题空间互不重叠。一台设备被攻破或写坏，影响面锁死在它自己的主题内。

**为什么。**

- 设备**天然异构**：C3 走 HTTP 被推，P4 走 MQTT 对话（带保活 / 去重 / 4 KB 切片），
  小车要异步回执。强套一层通用路由，得到的是分支堆砌 —— 代码更长，却没有真通用。
- **安全边界跟进程边界对齐**：一个持有所有设备凭据的进程，攻破即全失；
  拆成多个进程，攻破一个只丢一个。

**怎么检验。**

| 判据 | 本仓的做法 |
|---|---|
| 新增设备只加两 / 三处 | 适配器目录 + systemd 单元（走 MQTT 再加一个 ACL 角色），核心代码不动 |
| 删掉一台设备不影响其余 | 主题、凭据、进程都独立 |
| 设备之间互相看不见 | ACL 按主题收窄；`hub/command/<设备>` 各订各的，**不订 `hub/command/#`** |
| 失败范围可预期 | 一个适配器崩溃，只影响它自己那条链路 |

> 边界的具体划分（哪些通用、哪些必须定制）：
> [ARCHITECTURE.md](ARCHITECTURE.md#四架构边界这不是通用-mqtt-底座)。

## 这三条约束的是我们自己

规约不是写给别人的标准，是我们做取舍时的依据：

- 要不要为了"少写一个适配器"做通用路由？→ **不要**，那会用隔离换便利。
- 要不要为了"少配一个证书"把 8883 放宽？→ **不要**，那会用可验证性换便利。
- 要不要为了"看起来完成了"把超时当成功？→ **不要**，那是把不可回滚的动作交给猜测。

做不到的部分，我们写在 [ARCHITECTURE.md 的已知限制](ARCHITECTURE.md#五已知限制)里 ——
**写得出来，才说明真的想过。**
